# 작업 흐름

> 프로젝트별 스택·배포처·통합은 **프로젝트 CLAUDE.md**에 명시. 이 글로벌 파일은 스택 무관한 공통 작업 원칙만 담는다.

## 세션
- 시작 시 MEMORY.md, 핸드오버 파일 먼저 읽고 현재 상태 파악
- 종료 시 3단계: (1) `~/.claude/scripts/session-end.sh {경로}` (2) 회고 요약 (3) MEMORY.md 기록
- `/compact` 의존 금지 — 명시적 핸드오버 작성

## 구현
- 스펙 우선: `openspec spec` → 구현 (`/opt/homebrew/bin/openspec`)
- 자율 구현: TodoWrite (최대 15개) → 3개마다 commit → 실패 3회 보고
- 기획 세션: 반드시 구체적 산출물 (markdown, config) 남기기
- **UI 변경 시 검증 플로우**: 코드 수정 → dev 서버 확인 → 브라우저 시각 확인 → 완료 보고. 빌드 통과만으로 완료 선언하지 않음
- **"완료" 보고 전 체크**: 수정한 각 항목을 실제 동작으로 확인했는가? 증거(스크린샷/curl/브라우저 확인)가 있는가?

## 리팩터링/정리
- 공유 유틸 추출 후 반드시 `tsc --noEmit`로 unused import 검증 (예: GRADIENT_COLORS import했지만 getGradient만 사용)
- 상수 중앙화 시 모든 소비자의 값 불일치 확인 (예: bg-sky-400 vs bg-sky-500) → 정규 값 결정 후 일괄 교체
- 파일 삭제/이동 후 잔여 파일 확인 (`ls` 또는 `git status`로 빈 디렉토리/잔여물 검증)
- 미커밋 파일 많을 때: 논리적 단위로 분리 커밋 (auth/기능/정리), 커밋 간 빌드 깨지지 않도록 의존성 순서 고려

## 커밋 전략 (대량 변경)
- 1개 파일을 2개 커밋에 나눌 수 없음 (git add -p 비대화식 환경 불가)
- 의존 관계: 새 export를 import하는 파일은 export 정의 파일과 같은 커밋에
- 논리적 분류 예시: (1) 인프라/auth (2) 기능/UI (3) 정리/최적화

## TDD 학습
- 정규식 테스트 URL 작성 시 타겟 패턴만 매칭하는지 확인 (다른 패턴 요소가 오탐 유발)
- 다단계 fallback 테스트: 각 strategy의 skip 조건이 다음 strategy에 미치는 영향 검증
- 단위 테스트 통과 후 E2E로 실제 데이터 흐름 재확인 (정규화 파이프라인 등)

- 작업 중 꼬이면 즉시 멈추고 재계획 (점진적 패치 금지 원칙과 연결)
