# lean-polish — 시각 결과물 마감 규칙과 검증

목표: **만든 사람이 "됐다"고 말하기 전에, {{OWNER_TITLE}}이 지적할 결함을 먼저 찾아 고친다.** 규칙은 실제 시각물 작업에서 반복해서 나온 지적을 모은 것이다.

## 언제 쓰나

- 시각 결과물(SVG·HTML·PNG·슬라이드·상세페이지·문서 PDF)을 새로 만들거나 고칠 때
- 다른 스킬(슬라이드·상세페이지 스킬 등)이나 서브에이전트가 만든 시각물을 보고하기 전에 점검할 때
- 사용자가 "여백", "균형", "낡아 보임", "글자 위치"를 말할 때

## 규칙 7개

1. **2026년 감각으로 만든다.** 2000년대 자료처럼 보이면 안 된다.
   - 쓰지 않는다: 굵은 색 테두리, 채운 원 배지, 클립아트(자물쇠·연필 같은 그림 아이콘), 묵직한 삼각 화살표, 원색 장식.
   - 쓴다: 얇은 1px 경계, 연하게 채운 면, 큰 둥근 모서리(16~24), 강조색 하나(의미색은 연한 배경), 1.6~2px 선 아이콘, 가는 화살표, 글자 위계(제목 20~22 / 본문 15~16 / 캡션 13).
2. **균형, 여백, 디테일이 내용만큼 중요하다.** 상하좌우 여백 대칭, 화면을 채우는 무게 중심, 같은 줄 카드의 높이와 내용량 균형. 카드 안 빈 바닥, 위쪽에 몰린 내용, 요소 겹침과 잘림, 카드 사이 간격 0은 모두 결함이다. **넘침 0만 확인하고 완료 보고하지 않는다.**
3. **상자 안 글자는 상자 중앙 기준으로 놓는다.** 글자 아랫선(baseline)을 숫자로 고정하면 렌더러마다 3~4px 어긋난다. 상자 중앙 y에 `dy="0.38em"`(한글 기준 세로 중앙)처럼 글꼴 크기에 비례하는 방식으로 놓는다. 알약, 버튼, 배지, 카드 제목, 표 행 모두 해당한다. (`references/svg-recipes.md`)
4. **시각 확인은 {{OWNER_TITLE}}이 실제로 보는 앱 안 브라우저에서만 한다.** 맥 미리보기(qlmanage), 헤드리스 캡처 등 다른 렌더러로 본 것은 확인으로 치지 않는다. (`references/verify-recipe.md`)
5. **원본 크기로 한 장씩 본다. 고친 직후 다시 보고 나서만 "확인했다"고 보고한다.** 일부만 다시 보고 전부 확인했다고 말하지 않는다. 보지 못한 것은 "확인 안 함"이라고 쓴다.
6. **줄여서 보아도 읽혀야 한다.** 책(약 600px 폭)이나 모바일(860px 상세페이지가 줄어든 폭)에서도 읽히게, 설명 글자는 도면 폭 820 기준 15px 이상, 붉은 설명 같은 안내 글자는 16~17px을 쓴다. 도면 폭이 클수록 글자가 작아 보인다.
7. **보고 전에 위 1~6을 체크리스트로 스스로 감사한다.** {{OWNER_TITLE}}이 지적하기 전에 결함을 먼저 찾는다.

## 자기 감사 체크리스트 (보고 전 한 장씩)

| 항목 | 확인 방법 | 통과 기준 |
|---|---|---|
| 낡아 보이는 장식 | 장식 요소 훑기 | 굵은 색 테두리, 채운 원 배지, 클립아트, 묵직한 화살표가 없다 |
| 가장자리 여백 | 창·카드의 좌우상하 여백 비교 | 좌우, 상하가 서로 비슷하다 |
| 같은 줄 카드 | 높이와 내용량 비교 | 높이가 같고 내용량이 크게 다르지 않다 |
| 카드 안 빈 바닥 | 마지막 요소 아래 공간 | 위 여백의 1.5배 안쪽 |
| 쏠림 | 화면 전체 무게 중심 | 위쪽 3분의 1에만 몰리지 않는다 |
| 겹침·잘림·간격 0 | 번호표, 화살표, 말풍선, 카드 사이 | 글자를 가리거나 창 밖으로 잘리는 것이 없다 |
| 글자 중앙 | 상자 안 글자를 확대(zoom)해서 확인 | 상자 중앙선과 글자 중앙선이 눈으로 일치 |
| 글자 크기·위계 | 폭을 줄여 본다 | 줄여도 읽히고 제목·본문·캡션이 구분된다 |
| 줄바꿈 | 한국어 문장 끝 | 마지막 줄에 짧은 한 단어만 남지 않는다 |
| 의미색 | 빨강·주황 사용처 | 주의가 필요한 곳에만 쓴다 |

## 검증 절차 요약 (자세한 명령은 `references/verify-recipe.md`)

1. 결과물을 파일로 만든다(SVG·HTML 등).
2. `scripts/serve.sh start <폴더>`로 로컬 서버를 띄운다. (`file://` 주소는 앱 안 브라우저가 캡처할 수 없다.)
3. 앱 안 브라우저에서 한 장씩 열어 스크린샷으로 본다. 글자 위치는 확대해서 본다.
4. 결함을 고치면 고친 장을 다시 열어 다시 본다.
5. 끝나면 `scripts/serve.sh stop`으로 서버를 종료한다.
6. 앱 안 브라우저가 그려지지 않으면(`Browser pane is not displayed`, 세션이 창에 열려 있지 않을 때) 확인을 보류하고 **"확인 안 함"으로 보고한다. 다른 렌더러로 대신 확인했다고 말하지 않는다.**

## 보고 형식

- 확인한 장수: N/M장(앱 안 브라우저)
- 고친 결함: 항목별로(예: 번호표가 창 위로 잘림, 이름과 시각 겹침)
- 확인 못 한 것: 있으면 이유와 함께. 최종 산출물이 다른 렌더러(PDF, EPUB, 모바일)를 거친다면 그 렌더러에서 따로 확인해야 한다고 적는다.

## 다른 스킬과의 관계

- `intranet-style`: 인트라넷 화면은 그 스킬의 토큰과 규격이 우선이다. 이 스킬은 마감 점검에만 쓴다.
- 전자책 그림: 사용자 조작을 설명하는 그림은 도식이 아니라 **화면 캡처(또는 최대한 비슷한 재현)에 붉은 표시(네모, 번호, 화살표, 설명)**를 얹는 방식으로 만든다(`references/svg-recipes.md`).
