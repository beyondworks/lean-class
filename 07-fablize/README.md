# 07-fablize — 작업 방식 하네스

## 이게 뭔가

`fablize`는 **Claude가 일하는 방식 자체를 바꾸는 규칙 블록**입니다. 스킬처럼 "무엇을 할 수 있나"를 늘리는 게 아니라, 매 작업의 **착수·검증·보고 방식**을 규정합니다.

설치하면 `~/.claude/CLAUDE.md`에 `<!-- FABLIZE:BEGIN … END -->` 블록이 들어가고, 작업 신호에 따라 해당 규율이 자동 적용됩니다.

핵심 조항:

| 신호 | 적용되는 규율 |
|---|---|
| **항상** | 결론부터 · 요청 범위 밖 리팩터 금지 · 완료 주장은 이 세션 도구 결과로만 |
| **절제(restraint)** | 계획 나열 없이 첫 도구 호출로 착수 → 한 번에 완성 → 가장 직접적인 관찰로 1회 검증 → 통과하면 멈춤(초록 결과 재검증 금지). 보고는 문서가 아니라 짧은 노트 |
| **순차 다중 산출물** | 목표 엔진(`goals.py`)으로 create→next→checkpoint→검증 게이트. 증거 없는 완료 불가 |
| **디버깅·리뷰** | 재현 먼저 → 경쟁 가설 3개 이상 → 가설별 증거 → 인과 사슬 → 전후 검증 |
| **렌더 산출물(HTML·SVG·차트·UI)** | 실제 렌더러에서 돌려 눈으로 본 뒤 고친다. 정적 검사는 관찰이 아니다 |

가장 체감이 큰 건 **restraint**입니다. "계획 먼저 말하고 → 만들고 → 여러 번 다시 확인하고 → 긴 보고서"라는 습관을 "바로 착수 → 한 번 완성 → 한 번 검증 → 짧은 노트"로 바꿉니다.

---

## 설치

```bash
bash 07-fablize/install-fablize.sh global
```

`install.sh`가 자동으로 호출하므로 보통은 따로 실행할 필요가 없습니다.

**파일을 이 패키지에 담지 않았습니다.** fablize는 제3자(fivetaku) 저작물이라 재배포하지 않고, 설치 시 원본 레포에서 받아옵니다.

```
https://github.com/fivetaku/fablize  →  ~/Code/fablize  →  setup/setup.sh global
```

받아오기에 실패해도(네트워크·git 미설치) 설치 전체는 계속 진행됩니다. 하네스만 빠집니다.

## 되돌리기

```bash
bash ~/Code/fablize/setup/uninstall.sh global
```

`setup.sh`는 주입 전 `CLAUDE.md`를 `.fablize-bak.<타임스탬프>`로 백업합니다.

---

## 설치 순서가 중요합니다

fablize는 `~/.claude/CLAUDE.md` **끝에 블록을 덧붙이는** 방식입니다. 그래서 순서가 이렇게 되어야 합니다.

```
1) 06-rules 설치  → CLAUDE.md 생성
2) 07-fablize 설치 → 그 뒤에 블록 append
```

거꾸로 하면 06-rules가 CLAUDE.md를 덮어쓰면서 블록이 날아갑니다. `install.sh`는 이 순서를 지킵니다. 수동 설치할 때만 주의하세요.

## 참고 — 확장판

원저자가 별도로 운영하는 확장판(기여자용, 팩·평가 러너 추가)이 있습니다. 접근 권한이 있는 사람만 받을 수 있어 이 패키지에서는 다루지 않습니다. 공개판만으로 위 5개 조항은 모두 동작합니다.
